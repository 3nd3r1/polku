# Concept: Polku (working name)

*Polku* is Finnish for "path". Decisions so far (Fri 13.11 20:00): AstraZeneca challenge, **lung cancer pathway only**, **nurse callback** as the outcome, **TS full-stack**, 2 generalist devs. Voice is a stretch goal.

## One-liner

A patient front door and pathway ontology for Finland's upcoming standardised cancer pathways: patients describe symptoms, a deterministic engine matches them to published referral criteria, a nurse calls back within the target time, and every step runs on a clock the county can see.

## Architecture

```
Patient chat (web, voice later)
   │ free text, Finnish/English
   ▼
LLM extractor ── outputs typed SymptomObservation[] with quoted spans + confidence
   │ (LLM never decides anything)
   ▼
Rules engine ── matches observations against Criterion objects from the pathway definition
   │ deterministic, cites the source of every criterion
   ▼
Actions ── OpenFastTrackCase → NurseTask (callback deadline) → StepClock starts
   │ every action typed, validated, permissioned, audit-logged
   ▼
Ontology store (Postgres) ──► Nurse inbox ──► County view (roll-up + recommendations)
```

## Ontology (Palantir-style: objects, links, actions)

**Object types**
- `CancerPathway`: lung, version, source refs
- `PathwayStep`: suspicion → primary-care assessment → referral → diagnostics → MDT decision → treatment start. Each has a `maxDays` target (source-cited)
- `Criterion`: entry/referral criterion with an expression over symptom codes, risk factors and age. `sourceUrl`, `sourceQuote`
- `SymptomCode`: controlled vocabulary (e.g. haemoptysis, persistent cough > N weeks, unexplained weight loss…)
- `Patient` (synthetic), `SymptomReport`, `SymptomObservation`
- `Case`: patient in pathway, current step, status
- `StepClock`: started, deadline, breached?
- `NurseTask`: callback due, assignee, outcome
- `County` (hyvinvointialue), `Unit` (health centre, hospital)
- `PublicIndicator`: real stats with source (incidence, stage distribution, survival per region)

**Links:** Case→Patient, Case→Pathway, Case→County, StepClock→Case+Step, Criterion→Pathway, Observation→SymptomCode, Observation→Criterion (matched)

**Actions** (each with input schema, preconditions, permitted role, audit entry)
- `SubmitSymptomReport` (patient)
- `OpenFastTrackCase` (system, only when a criterion matches; status `pending_review`)
- `ConfirmCase` / `DismissCase` (nurse; a human always decides)
- `LogCallback` (nurse)
- `AdvanceStep` (clinician; stops one clock, starts the next)
- `EscalateOverdue` (system, when a clock nears its deadline)

**Pathway as code:** the lung pathway is one strict typed definition file (TS + zod), versioned, every criterion with a citation. This is the "strict definitions, no prose specs" idea in practice.

## County view

- Per county × step: median days vs target, % within target, breaches. **Synthetic** cases, generated by a simulator calibrated to real public numbers (incidence and population per county) plus labelled assumptions.
- Real public indicators shown next to it with sources (Syöpärekisteri, Sotkanet, NORDCAN survival gap).
- Recommendations: rule-triggered, with an LLM-written narrative constrained to cited numbers. E.g. "County X: 62 % of referral→diagnostics steps breach target. Proposed: direct CT route from primary care (measure 2.5.2). Simulated effect: −9 days median."

## Clinical safety framing (judges will ask)

- No diagnosis, no AI triage. The LLM only structures language. Matching uses published criteria. A nurse confirms every case.
- Positioned as an implementation of national criteria, not a medical opinion.
- Synthetic data only, no personal data. EU AI Act and MDR considerations named in the deck.
